The problem

Fraud detection involves highly imbalanced observations, where traditional accuracy metrics can hide poor performance. This portfolio experiment focuses on risk scoring, explanation, and honest evaluation rather than making real banking security claims.

What I built

A complete ML pipeline: synthetic transaction generation, exploratory feature engineering, Logistic Regression model selection by validation PR-AUC, threshold tuning on validation data, and evaluation on a separate untouched test set. FastAPI supplies JSON endpoints consumed by a dashboard with Overview, Transactions, Risk Lab, and Model Insights.

Individual predictions include one-feature-at-a-time log-odds sensitivity estimates to a reference profile, showing how changing a feature influences the model output. These are not causal explanations.

Engineering stack

Python, Pandas, NumPy, scikit-learn, FastAPI, Pydantic, vanilla JavaScript, GitHub Actions and Docker.

Limitations & future work

The held-out test set precision is 17.1% and recall is 33.9%: this model would create false alerts and miss some simulated fraud. Future work includes probability calibration, concept-drift monitoring, stronger data validation, and evaluation on appropriately permissioned datasets.

Research demo only: All examples, labels and amounts are fictional. Scores are not validated real-world fraud probabilities. This project must not be used to approve, reject, or block real payments.
